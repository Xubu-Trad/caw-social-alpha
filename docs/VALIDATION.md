# Validation boundary

Alpha.20 passed **366/366 offline tests across 25 files**, with no failed, cancelled, skipped, todo or pending outcomes. The [115-input manifest](../evidence/CODE_SHA256SUMS.txt), [current receipt](../evidence/TEST_RESULTS.json) and [alpha.19 receipt](../evidence/ALPHA19_TEST_RESULTS.json) keep releases distinct. The build rehashed 22 assets. Frontend interaction behavior is unchanged; no new browser result is claimed.

Three original Solidity sources compiled without diagnostics under 0.8.10 / optimizer 200 / London: the integrated probe, fixed registry and contract-signature fixture. The new local fork ran 56 transactions, including two funding transfers and a 54-transaction history. Nine signed posts settled and 22 deliberate invalid transactions reverted. It made 1,416 local RPC requests and 40 forwarded historical reads, stopped after 62.406 seconds and used a measured peak 40,976,384 bytes. The node and both listeners were independently confirmed stopped.

The 12 new named evidence tests check the full transaction sequence against raw requests/receipts, source pins, exact signed/post bytes, fee allocation, accounting and finite failure cases. The JavaScript and Python readers were separately authored from the contract and run after the original local node stopped. Their complete outputs agree. They share no application/writer accounting helpers; each uses a retained Keccak implementation. Both consume one provider-derived capture and a supplied manifest. Neither reauthenticates signatures, block hashes, receipt/transaction tries, consensus, finality or current authority. The tests explicitly retain that limit, including a signature-only mutation which this reader does not authenticate. Local automining produced some equal-timestamp blocks; accepting that captured order is not Ethereum consensus validation.

Captured rejection cases cover duplicate submission, wrong chain/contract/fee/profile/owner, changed text, high-S signatures, expiry, changed distribution, insufficient unlocked credit, locked withdrawal, empty eligible pool, stale epochs and malformed/oversized text. NFT transfer to a new signer and return, a non-staked owner's withdrawal, and bounded ERC-1271 responses were exercised. A second submitter's duplicate is sequential local execution, not a concurrent public-network race. All nine charges distribute to the other staked IDs with one dust base unit each. Other accounts controlled by the payer's wallet remain eligible under this proposed account-based policy.

Earlier failed attempts are preserved: a compiler stack limit, a code-bearing familiar test address and a text-transport-corrupted Unicode fixture. The final run uses fresh public test scalars with observed empty historical code and ASCII-escaped Unicode inputs. The [known-account failure](../experiments/paid-action/known-account-failure.json) is not a delegated-account success. London execution does not establish EIP-7702 compatibility.

Historical token code/storage was retained. Local actors, including the public funding address ending dead, were impersonated and native gas balances fabricated; this gives no authority on the public chain. No real wallet, public broadcast/deployment, storage offload or deletion occurred. All 59 requirements and 15 conflicts keep their primary text/status. C-001 blocks registration; no alternative burn destination was adopted.

The new integrated contract still needs its own complete adversarial token/callback regression, realistic staking-scale design, delegated-wallet execution under current rules, reorg recovery and authenticated history acquisition. The earlier custody tests are historical evidence, not automatic coverage for changed code. Fixed test NFTs do not establish authentic username registration. Runtime pins do not establish honest dependencies. Source publication and same-team review are not external audit or community acceptance. Read [one signed, paid CAW](PAID_ACTION.md) and the [C-001 decision request](C001_DECISION_REQUEST.md).
