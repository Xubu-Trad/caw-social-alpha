# Build comparison — reference, evidence and next work

Review date: 2026-09-07. **GilgameshCaw/Caw is reference only.** Any future upstream contribution must target the relevant cawdevelopment repository. It is same-team source review, not independent security certification.

**Assessment:** our build is a useful original website and synthetic social/accounting demonstration. It is not yet a competing production protocol or compatible client for the reference contracts. Preparing a hosted fixture preview is reasonable after its exact release checks. A wallet, custody, testnet or production protocol deployment requires a separate implementation and evidence program. Adding more reference features does not close those gates.

## Findings that should drive the next work

### Before a hosted fixture preview

1. **Make the release internally consistent.** Finalize the current edits, record exact hashes, rerun appropriate checks and regenerate the deterministic package. Update contemporaneous status paragraphs that still say 40 tests, browser blocked or no media tests. Preserve older run records as historical evidence. Do not call a changed app covered by the prior 44-test snapshot.
2. **Exercise the advertised media path.** Current automated video coverage uses candidate headers and direct metadata validation; it does not decode/play a real video. Test a small known-safe MP4/WebM, valid JPEG/WebP, replacement during load, navigation/page lifecycle, removal during playback and timeout/failure cleanup. If a format cannot be tested, qualify its status or keep it out of the offered preview scope. No uploaded data or real private media is needed.
3. **Check the actual host boundary.** The loopback server deliberately rejects other Host/Origin values and is not a production server to expose. A static host must independently apply MIME types, restrictive CSP, isolation, framing and no-referrer policies; review host-injected scripts. An artifact digest beside mutable files is consistency evidence, not trustworthy authentication by itself.
4. **Preserve privacy, provenance and accurate copy.** Serve an exact public allowlist; no private/source/run directories, account data or selected media. The user already authorized public preservation of the exact article PNG, and the same asset was selected for this build. Preserve that authorization/provenance context without asking again solely because an app package exists. Do not infer a blanket artist license or official branding from it. Our original code does not require permission to reuse someone else's implementation because none was copied.

### Before protocol work can be called test-deployable

The source differences below are concrete comparison evidence, not claims of live vulnerabilities:

- **Burn and authority:** the minter's dead-pattern destination differs from the adopted 0x0 text, and the PathwayExpander retains an owner path. Verify the actual token and full deployment authority graph; do not claim renunciation from documentation. [Pinned minter](https://github.com/GilgameshCaw/Caw/blob/518b4bf1598775b677e1d22888b587892bfb812b/solidity/contracts/CawProfileMinter.sol#L390), [pinned expansion function](https://github.com/GilgameshCaw/Caw/blob/518b4bf1598775b677e1d22888b587892bfb812b/solidity/contracts/PathwayExpander.sol#L138).
- **Economics and exits:** reference dynamic pricing, network fees, thin-pool handling and optional withdrawal conditions are substantive choices. Our fixed-weight rejection policy is also a demo choice. Establish a reviewed decision for each; require conservation, exact token backing, fresh authority and a user-controlled exit before real custody. [Pinned network fee authority](https://github.com/GilgameshCaw/Caw/blob/518b4bf1598775b677e1d22888b587892bfb812b/solidity/contracts/CawNetworkManager.sol#L265), [pinned withdrawal gating](https://github.com/GilgameshCaw/Caw/blob/518b4bf1598775b677e1d22888b587892bfb812b/solidity/contracts/CawProfileMinter.sol#L331).
- **Signed intent and honest progress:** inspect the reference's scheduled editing/worker mismatch before designing scheduling. Editing readable text must replace its authorization; queue insertion must not mean final publication. [G-030 exact source evidence](../sources/reference_2026_09_07/GILGAMESH_FEATURE_MAP.md#g-030). The same principle applies to our future signatures, relayers and release configuration.
- **Recovery:** complete public reconstruction remains a deliverable, not a slogan. The reference's own backlog marks its historical reproducer unbuilt; our JSON format can accept a fully self-consistent rewritten history because it has no cryptographic provenance. DMs, media and local preferences need separate recovery rules. [Pinned rebuild backlog](https://github.com/GilgameshCaw/Caw/blob/518b4bf1598775b677e1d22888b587892bfb812b/docs/PROOF_OF_COMPLIANCE_BACKLOG.md#L114), [our data limits](DATA_AVAILABILITY_AND_REBUILD.md).

Useful next interface work, after the release boundary is sound, is focused: navigable references and receipts; local activity summaries; explicit search and hidden-content state; accessible media controls. Scheduling, marketplace escrow, passkey recovery, custom DMs and cross-chain infrastructure should not be rushed into the fixture preview to make a checklist look complete.
