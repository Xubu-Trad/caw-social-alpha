INDEPENDENT OPERATION / PROPOSED

The project should outlast its builders.

Closing one website must not close everyone’s account. Losing one domain, relay or storage provider must leave a usable alternative.

More than one entrance.

Portable clients, alternate hosts and content-addressed releases. A familiar domain can be a shortcut; it cannot be the only way in.

No exclusive switch.

The proposed custody core has no builder-controlled pause, seizure or upgrade power. Published code and deployed authority still need independent verification.

Recover the actual record.

Independent operators must be able to restore accounts, actions and required content from public evidence. A hash alone cannot supply a missing file.

No honest design can guarantee forever. Networks, devices, storage, funding and connectivity can fail. We will test specific failures and publish the limits.

IMAGES + VIDEO

Choose. Review. Publish deliberately.

The intended media flow shows the file, caption, metadata choices, cost and storage terms before publication. Video plays only when asked. Missing media stays visibly missing.

Images follow the manifesto’s frontend-hosting boundary. Video is an added product requirement. Neither changes who controls protocol balances.

The current Media view is a local preview only. It sends nothing, preserves the original file, and clears on navigation or refresh. Removing a preview does not erase a file or any independently hosted copies.

Read the source. Question the claims.

R2 calls for public code, contributions, peer review and an agreed release. It rejects developer backdoors, proxies and multisigs. A review repository is a beginning; it does not prove those deployment requirements.

CAW identities are pseudonymous; public activity can be linked. Imageboard presentation does not make an account anonymous.
